# Post-hoc acceptance — F-001 (mu-plugin scope expansion)

## Finding (verbatim from team_190 verdict)

> `sfagent-allow-json.php` was changed beyond the LOD400 primary media scope. The SVG MIME addition is a legitimate infrastructure-class adaptation for media migration, but the same MU plugin also adds a Yoast title fallback. This is operationally effective and not a blocker, but it is post-hoc scope expansion and should be explicitly accepted by team_110/team_00.

## team_110 acceptance ruling

**ACCEPTED** with the following architectural justification:

1. **SVG/JSON MIME allowance** — operationally required for Batch 002 to upload all 694 source media types. The first media item on old prod is `sfagent-crop-book-manifest-of-urls.json` (application/json). WP rejects JSON uploads by default; allowing them via mu-plugin is the minimum-friction path. This is **infrastructure-class** per the project's "no new plugins unless infrastructure-class" rule, and an mu-plugin is the canonical mechanism for such cases (no admin UI, version-controlled, theme-independent).

2. **Yoast title fallback** — addresses AT-1 finding from Batch 001 (Yoast meta_template lacking "Unless"). The mu-plugin adds the fallback at runtime, avoiding a Yoast options table write that would have required additional admin UI interaction. Both mechanism and outcome match the LOD400 Batch 002 §8.5.2 cleanup task spirit.

3. **Bundling rationale** — combining both adaptations in one mu-plugin is justified because:
   - Both are runtime-injection patterns (filter callbacks)
   - The mu-plugin file already existed (named for sfagent, but functioning as a generic site adapter)
   - Splitting them would require either (a) a new mu-plugin file (more files to track) or (b) duplicating bootstrap code

4. **No scope creep on theme/CSS/theme.json** — verified by AT-9 empty diff. The expansion is contained within mu-plugins, which is the canonical place for site-level adaptations.

## Conditions for acceptance

- The mu-plugin file's name (`sfagent-allow-json.php`) is misleading given its current scope. **RECOMMENDED CLEANUP** (V300 or follow-up): rename to `nimrod-bio-site-adapters.php` or split into discrete files. Not blocking for V200 cutover.
- F-003 (validate_aos Check 12 fail) remains a separate finding — requires cleanup OR formal waiver before P005-WP002 production cutover. Not blocking this PR merge.
