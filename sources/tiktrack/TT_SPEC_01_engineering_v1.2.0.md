### **Engineering Specification Document: TikTrack v1.2.0 \#\#\#\#\# 1\. Architectural Philosophy: Active Quality Assurance (QA) TikTrack v1.2.0 signifies a strategic evolution from a retrospective ledger to an Active Quality Assurance (QA) ecosystem. The system is architecturally optimized for the Swing Trader Profile (3–15 trades per week) . For this specific cohort, the manual overhead of linking trade plans is categorized as an intentional "discipline tax"—a forced review moment essential for methodology hardening. The core of this ecosystem is the Behavioral Mirror , a clinical framework designed to intervene in the trader’s decision-making loop to mitigate the "hope and ego" biases that erode profitability. This is codified through the "Micha OS" methodology, which integrates dynamic volatility-based stop-loss levels (ATR Traffic Light) and strict risk enforcement (the Death Kiss 150 Law). The technical anchor for this intervention is the Plan Snapshot, an immutable database record captured at the moment of first execution. By freezing entry, stop-loss, and profit targets, the system prevents the unconscious revision of the trading thesis during live price action. To reinforce this habit, the UI triggers a non-blocking intervention banner for incomplete plans: השלמת התוכנית שלך תשפר את הניתוח — השלם עכשיו (Completing your plan will improve analysis—complete now). The integrity of this "Digital Twin" relies on the underlying data structures defined in the following technical specifications. \#\#\#\#\# 2\. Database Migrations & Phase 2 Data Model The transition to Phase 2 prioritizes financial precision and institutional readiness. Every data mutation is governed by ADR034 (Single Source of Truth) , which mandates that the PostgreSQL database remains the absolute authority, strictly forbidding application-layer state writes to ensure cumulative integrity. \#\#\#\#\#\# Technical Implementation of Migrations \* Migration 0019 (D29-NEXT): Introduces the user\_trade\_defaults table for risk parameter persistence. It expands the trades table with a three-column logic and a plan\_field\_sources JSONB object. This object tracks field-level provenance using keys: user, inferred, and first\_execution. The is\_plan\_complete boolean transitions to TRUE exclusively via explicit user intervention; automated inference engines are restricted to FALSE to maintain data fidelity. \* Migration 0022 (D32): Implements the daily\_portfolio\_snapshots table. This serves as the "Portfolio State" engine, enabling the derivation of Sharpe Ratio, CAGR, and Max Drawdown. \* Migration 0030–0032 (Notifications & Account Deletion): \* Migration 0030: Deploys a 6-table notification infrastructure (including notification\_outbox and notification\_aggregator\_windows) with idempotency mechanisms via idempotency\_key and a 5-stage outbox delivery lifecycle. \* Migration 0032: Implements the "Account Deletion" protocol. This migration flips Foreign Key (FK) constraints from RESTRICT to CASCADE for the following 5 tables: executions, tags, broker\_connections, sync\_log, and tag\_categories. \#\#\#\#\#\# Precision Standards (ADR034 Compliance) To prevent rounding errors inherent in IEEE 754 floating-point math, all financial calculations must utilize the following standards: | Data Type | SQL Type | Application Scope | | \------ | \------ | \------ | | Prices & Quantities | NUMERIC(20, 8\) | Core execution-layer and market data. | | P\&L & Cash Flows | NUMERIC(20, 6\) | Realized/Unrealized P\&L and dividends. | | Portfolio Values | NUMERIC(18, 4\) | total\_value and account-level rollups. | | Risk Ratios | NUMERIC(6, 4\) | R:R ratios and default\_risk\_pct. | These structured data standards provide the high-fidelity input required for the AI integration layer. \#\#\#\#\# 3\. D25 AI Architecture & Cost Governance The D25 "Skeptical Coach" requires a multi-layered governance system to manage the high token consumption of longitudinal analysis while maintaining provider flexibility. \* \*\*Similarity Cache:\*\*Redundant API calls are suppressed via SHA256 prompt signatures. The tier-2 structured similarity lookup checks for matching templates/subjects within a 24-hour temporal window. \* Delta Mode ( cache\_tier: DELTA ): For ongoing trades, the system executes focused updates by analyzing only the delta between the current state and the previous analysis, significantly reducing costs for long-duration positions. \* Provider Governance: TikTrack maintains a Bring Your Own Key (BYOK) model. Supported providers (Anthropic, OpenAI, Grok, Perplexity) are stored in user\_data.user\_api\_keys with is\_verified (Boolean) and last\_verified\_at (Timestamp) fields for architectural completeness. \* Budgetary Triggers: The ai\_user\_budget service tracks current\_spend\_usd against a limit\_usd for specific period\_type (daily/monthly). Hard percentage triggers (100%) halt processing, while soft triggers (80%) fire user alerts. This governance layer ensures economic viability as the platform transitions to wider deployment. \#\#\#\#\# 4\. Six-Stage Rollout & Deployment Policy Staged deployment is mandatory to maintain "Digital Twin" accuracy and stabilize the concurrency model. 1\. Stage 1: Dogfooding: Internal validation on PostgreSQL 16\. Mandatory benchmark: clean pass of validate\_aos.sh with a "0 FAIL" requirement. 2\. Stage 2: Pilot: Access for 10 users via Tailscale-gated infrastructure to test D32 (Portfolio State) and DATA\_ERROR notifications in lab conditions. 3\. Stage 3: Cloud Hardening: Migration to AWS. Activation of the EncryptionService with a Key Rotation mechanism (Primary vs. Legacy slots). Strict ALLOWED\_ORIGINS CORS policies enforced. 4\. Stage 4: Concurrency Scale: Expansion to 100-500 users. Implementation of FOR UPDATE SKIP LOCKED patterns in NotificationService and compute\_portfolio\_snapshots to mitigate deadlocks. 5\. Stage 5: B2B/Organization Model: The architecture decouples identity from the per-user ULID model, encapsulating data within a Multi-tenant Organization Model to facilitate institutional actor-tracking and audit compliance (Full Audit Log). 6\. Stage 6: Premium Tier: Commercialization via feature flag-gated modules. This progression ensures technical scaling and organizational isolation evolve in parallel. \#\#\#\#\# 5\. Scalability & Concurrency: Infrastructure Evolution Managing asynchronous consistency in a financial environment requires strict isolation of background jobs and job-run consistency. \* Current State: Utilizes a PostgreSQL-backed queue. Workers use the FOR UPDATE SKIP LOCKED syntax for the NotificationService and snapshot computation. \* Target State (Phase 3): To support increased throughput and minimize database contention during concurrent updates, the system will migrate to a Redis-backed worker queue (Celery/ARQ), moving task state out of the relational engine. \* Background Jobs: \* ibkr\_daily\_sync: Full account sync (23:50 UTC). \* compute\_portfolio\_snapshots: (23:55 UTC). Handles NULL in account\_id as user-level rollups. Historical reconstruction is managed via the Backfill CLI (scripts.backfill\_portfolio). \* sync\_exchange\_rates\_eod: (23:30 UTC) for multi-currency FX rollups. \* purge\_deleted\_accounts: (02:00 UTC) hard-purge for accounts scheduled via Migration 0032\. \#\#\#\#\# 6\. Application Governance & Module Isolation The modular design allows for diverse trading style support without codebase pollution. \* Gating Mechanism: Premium modules use the require\_ dependency. Unauthorized access results in a MODULE\_DISABLED 403 response. The frontend implements an isModuleDisabled403 wrapper to present a "Locked-state UX." \* Data Isolation & Encryption: The EncryptionService (Fernet AES-128-CBC \+ HMAC) protects sensitive institutional data, including telegram\_chat\_id\_encrypted and broker credentials (e.g., ibkr\_username\_encrypted). \* Governance Constraint (ADR034): Direct database writes from the application layer are strictly forbidden. All mutations must traverse core service layers to maintain the integrity of the Single Source of Truth. As of May 2, 2026, the architecture is certified as TikTrack v1.2.0 "LOD500\_LOCKED" .**
