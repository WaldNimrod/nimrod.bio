# LOD400 — NB-S002-P005-WP002 — Production cutover

## 1. Mission

Take the rebuilt site from `nimrod-bio-2026.s887.upress.link` (dev) to `nimrod.bio` (production), preserving SEO, redirects, and zero downtime within reason. Replace the legacy Flatsome site without losing the migrated content, the redirect map, or the SMTP delivery path. Execute Search Console handoff per the runbook from P004-WP002.

## 2. Pre-cutover state assumed

- Dev site: `https://nimrod-bio-2026.s887.upress.link` — fully functional, 22 migrated posts, all 7 templates active, SMTP via wp-mail-smtp working, 301 redirects in MU plugin + .htaccess block, Yoast active
- Production site: `https://www.nimrod.bio` — legacy Flatsome, full backup taken by Team 00 (per V100 context note)
- All V200 carry-forwards to V300 documented (broken link, Lighthouse uplift)
- DNS for nimrod.bio: managed by uPress; CDN: Cloudflare in front per CLAUDE.md hosting notes

## 3. Cutover strategy — locked decisions

| Decision | Choice | Rationale |
|---|---|---|
| Mechanism | **In-place swap on same uPress account** (the dev site IS already in the same uPress; cutover = swap primary domain mapping) | Dev was provisioned within the prod uPress account specifically to enable this swap; no DB export/import needed |
| Approach | **uPress "publish to live" / domain remap** OR **manual swap** depending on uPress UI capability — confirmed by Team 00 at D-1 | Two options exist per uPress capabilities matrix; cleaner of the two chosen at D-1 |
| Old site fate | **Static `/archive/` snapshot** of legacy Flatsome site (per team_00 directive Q3=C from V200 open questions) — wget mirror → `nimrod.bio/archive/` on new install | Preserves SEO ballast for any URLs not in triage matrix |
| DNS TTL | **Lower to 300s 24h before cutover** if currently higher | Faster propagation if rollback needed |
| Rollback path | uPress backup restore + DNS revert | uPress backup taken as last step pre-swap |
| Smoke test | **Automated** via `scripts/cutover/post_cutover_smoke.py` + Team 00 visual ack | Same tools as P005-WP001 sweep, retargeted at prod URL |

## 9. Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| uPress "publish to live" UI does not exist for this plan tier | M | M | Fallback to manual swap (Team 00 verifies at D-1); rollback via uPress backup |
| DNS propagation slower than expected | L | L | TTL pre-lowered to 300s 24h prior; CF in front absorbs propagation |
| Cloudflare cache serves stale legacy content for hours | M | M | Mandatory CF purge step at T+0 to T+5 min; verify via `cf-cache-status: BYPASS` or `MISS` |
| MU plugins fail to load on prod (different file permissions) | L | H | team_10 verifies file mode 644 / dir 755 post-upload; auto-fix if needed |
| WP plugin config (wp-mail-smtp) doesn't carry over to prod | M | H | If swap is dev2prod copy, settings WILL carry. If manual, team_00 re-enters SMTP creds at T+10. Document both paths in runbook |
| Yoast indexing settings lost during cutover | L | L | wp_options table either carried (in-place swap) or re-applied by team_10; visible in admin UI |
| `WP_ENVIRONMENT_TYPE='local'` carried to prod → security weakening (App Password over HTTP via dev MU plugin) | M | H | K12 + K13 explicit; bump WP_ENVIRONMENT_TYPE FIRST before any post-swap action |
| 48h monitor catches a regression Team 00 can't reach team_100 | L | M | Monitor script writes daily log + sends email alert via wp-mail-smtp to Team 00 |
| Search Console rejects new property | L | M | Team 00 maintains ownership via existing verification; if cutover changes ownership, re-verify via DNS TXT or HTML file |
