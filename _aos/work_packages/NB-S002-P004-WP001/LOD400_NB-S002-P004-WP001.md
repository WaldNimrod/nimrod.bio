# LOD400 — NB-S002-P004-WP001 — Content migration

During migration: assign `world` + `flow_style` taxonomy to each post via team_00 interactive tagging tool, transfer media (uploads), and clean up the 4 P003-WP004 seed posts so blog has only real content.

## 4. Phases — execution flow

   PROD_REST_BASE=https://nimrod.bio/wp-json

4. team_00 confirms creation in COMPLETION addendum or chat. team_10 does NOT proceed to Phase 2 until creds provided.

⚠️ This is the **only manual prerequisite**. Everything else automated.

### Phase 2 — Fetch from prod

`scripts/migration/fetch_prod_posts.py`:

```python
# Pseudo:
# 1. Load url_migration_decisions_2026-05-25.json
# 2. Filter rows where decision IN ('redirect', 'keep') AND type='post' OR type='page' (heritage map)
# 3. For each, REST GET https://nimrod.bio/wp-json/wp/v2/{posts|pages}/{id}?_embed
# 4. Cache JSON to .migration-cache/raw/<id>.json
# 5. Print summary: fetched X posts + Y pages; failed N
```

Cache reduces network rounds on retries.

### Phase 3 — Generate tagging triage tool

`scripts/migration/tagging_export.py`:
- Reads `.migration-cache/raw/*.json`
- Outputs `docs/content_tagging_input.json` with per-post: ID, title, excerpt (~200 chars), date, original taxonomy hints (categories/tags)
- Builds `docs/content_tagging_triage.html` — interactive HTML similar to the URL triage tool, with for each post:
  - Row identifier (title, excerpt)
  - **Worlds:** multi-select checkboxes (soil/know/code) — default: all unchecked, team_00 must pick at least one
  - **flow_style:** single-select dropdown (lead/wide/tall/typo/quote/feature/brief) — default: `feature`
  - **Featured?** checkbox (used for T7 home page featured posts)
  - Notes textarea
  - localStorage auto-save, JSON export, JSON import

team_00 opens the HTML, tags all 22 posts (~10 min), saves `docs/content_tagging_decisions_<date>.json`, sends back. team_10 waits.

### Phase 4 — Import to dev

`scripts/migration/import_to_dev.py`:

```python
# Pseudo:
# 1. Load url_migration_decisions + content_tagging_decisions
# 2. For each post in cache:
#    a. transform_post() — strip prod URLs, fix Hebrew slugs, ensure /blog/ prefix matches the_post's new_url
#    b. REST POST to dev /wp-json/wp/v2/posts with:
#       - title, content, excerpt, date (preserve original publish date!)
#       - status: 'publish'
#       - slug: derived from new_url (e.g. 'יום-בגינה' for video1)
#       - meta: {_nb_seed: 'v200-migrated'}  ← tag so we can identify migrated posts later
#    c. After post creation, REST POST taxonomy assignment:
#       - world: term IDs from tagging decisions
#       - flow_style: term ID
# 3. For the 1 page redirect (2516 → /about/heritage/):
#    Heritage content is already hardcoded in T8 page-heritage.php (per P003-WP005).
#    This page is NOT recreated — only the 301 from old URL handles it (P004-WP002).
#    Skip page entity creation here.
# 4. For the 2 keeps (shook, blog):
#    - shook: REST POST as WP page with slug 'shook' — restore the market info page
#    - blog: SKIP — WP routes /blog/ to the posts archive (home.php) natively
# 5. Track id mappings: prod_id → dev_id (output to .migration-cache/id_mapping.json)
```

### Phase 5 — Uploads transfer

`scripts/migration/uploads_transfer.py`:

```python
# Pseudo:
# 1. wget --mirror --no-host-directories --cut-dirs=2 \
#      --reject 'index.html*' \
#      https://nimrod.bio/wp-content/uploads/ \
#      → .migration-cache/uploads/
# 2. ⚠️ Filter: only download files referenced in posts being imported (from content body grep).
#    Avoids transferring 991MB of historical media we don't need.
#    Maintain referenced_files set built by Phase 4 transform.
# 3. FTPS upload .migration-cache/uploads/* → /wp-content/uploads/ on dev
#    (use scripts/upress_ftps_upload.py with --recursive flag)
# 4. For each post body, regex-replace prod uploads URLs with dev URLs:
#    `https://nimrod.bio/wp-content/uploads/...`  →  `<dev-url>/wp-content/uploads/...`
#    OR
#    keep absolute URLs but ensure media is mirrored — simpler: rewrite to dev URL.
```

Estimated transfer: ~50-100MB (subset of 991MB total) for the 22 posts' actual referenced images.

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Prod REST API rate-limits at 22 sequential calls | LOW | LOW | Add 200ms sleep between calls; caching means at most one retry |
| Hebrew slugs URL-encode differently between prod/dev WP versions | LOW | M | Test M6 explicitly; if mismatch, use REST `?slug=` lookup not direct URL |
| Page entity for /blog/ collision with WP posts archive | M | LOW | Skip — WP routes /blog/ to home.php. Document in COMPLETION |
| 2516 "heritage" page text is also in T8 PHP — divergence | M | M | Per P003-WP005, heritage is hardcoded in T8 page-heritage.php. team_00 to confirm template matches actual prod content; if not, surface text edits via team_35 or hand-fix in PHP |
| Images >5MB might fail FTPS upload | L | L | Skip oversize, log, manual handling later |
| Prod has Cloudflare which may rate-limit wget | M | M | Use `--wait=2 --random-wait`; if blocked, fall back to FTP download of `/wp-content/uploads/` |
| `_nb_seed='v200'` vs `'v200-migrated'` collision in cleanup | LOW | M | Cleanup script does exact-match equality, not substring |
